# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is
A classroom activity (HNR-1303, Unit 5) about reinforcement learning, built around the NYT article
*"A.I.'s Rogue Behavior Starts With Its Training"* (PDF in the repo root). Students run Colab notebooks
that install this package from GitHub (`pip install git+…@maze-rl`), on a T4 GPU.

Read the docs before changing anything:

| Doc | Contents |
|---|---|
| `FINDINGS.md` | what has been learned, in plain language |
| `TEACHING.md` | the goals and the deliverables |
| `PLAN.md` | the current design |
| `EXPERIMENTS.md` | every experiment, with its prediction and its result |
| `HANDOFF.md` | in-flight work, where results live, the cluster workflow, gotchas |

## Commands
```bash
python -m venv .venv && .venv/bin/pip install -e . pytest      # setup
.venv/bin/python -m pytest -q tests                              # all tests
.venv/bin/python -m pytest -q tests/test_env.py::test_probe_solid_wall_stays_put   # one test
.venv/bin/python scripts/pretrain.py base --episodes 2000 --device cpu --evaluate 100 --out /tmp/x  # quick train + score
.venv/bin/python scripts/summarize_runs.py runs/<round>/*.json   # tabulate experiment results
```
Full-scale training and all experiments run on the campus cluster (`ssh hpc`, GPU node `thor`). See
`HANDOFF.md`.

## Architecture
`mazerl/` is one pipeline, from maze layouts to animations:
- **`maze.py`:** 18×18 layouts (14×14 maze plus a 2-cell outside band), generated by recursive division
  in three kinds (open / interior_break / outside_only). The 13,148 training layouts ship in
  `mazerl/data/`. The article's test mazes are ASCII files in `mazerl/scenarios/`.
- **`env.py`:** a batched PyTorch environment that steps hundreds of attempts at once, on CPU or GPU.
  - It holds the rewards (`Rewards`), the agent's observation (an egocentric 11×11 window of its memory,
    9 channels, plus an 8-way compass), and the bypass rule (attempts that end outside are left out of
    training).
  - Coordinates are padded by `PAD`. Subtract it to get arena coordinates.
- **`agent.py`:** a "vision" CNN plus "reasoning" layers. `perceive()` (vision plus the first reasoning
  layer) is the part reward-free pretraining trains; the rest decides.
- **`a2c.py`:** `train()` runs A2C over whole attempts, with a PPO-style clipped ratio. It returns a
  `Run` (agent, history, stage snapshots). All knobs live in `Settings`.
- **`perception.py`:** reward-free pretraining of `perceive()`: map completion plus the direction to
  unexplored ground.
- **`rollout.py`:** `record()` produces episode dicts for the player. It also has `evaluate()`,
  `standard_report()` (the fixed test suite) and `breakout_stages()`.
- **`player/`:** a self-contained HTML/SVG/JS animation player in the NYT style, rendered inline in
  notebooks. **`viz.py`:** matplotlib training curves.
- **`__init__.py`:** the student-facing API (`playback`, `training_grid`, `evaluate`,
  `load_pretrained`, …).

## Working conventions (from the user)
- **The article is inspiration, not a spec.** Choose designs for teaching value.
- **Explore settings by experiment:** write the prediction in `EXPERIMENTS.md` first, run the smallest
  set of runs that tests it, then evaluate. Never brute-force search.
- **Train models to convergence before comparing them.** Check learning curves; the learning rate
  anneals to zero, which flattens any run at the end.
- **When sources conflict, or the user's understanding differs from the build, stop and discuss.**
- **Work on branch `maze-rl`, and push often.** The user switches machines.
